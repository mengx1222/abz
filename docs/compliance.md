> **文档状态**：当前有效 · GREEN/YELLOW/RED + 规则引擎 + 人工审核流（已实现部分标注）
> 最后校准：2026-08-17


## 1. 合规概述

### 1.1 保险行业合规要求

安诊保 AI 副驾作为面向保险代理人的企业级 AI 销售辅助工具，必须严格遵守以下合规框架：

- **《中华人民共和国保险法》**：保险销售行为须真实、准确，不得有虚假陈述或误导性宣传。
- **《保险销售行为管理办法》**：销售人员应当客观、全面地向投保人介绍保险产品，不得夸大保险责任、隐瞒重要条款。
- **《关于规范金融营销宣传行为的通知》**：金融营销宣传不得含有虚假、夸大或误导性内容，不得对收益或回报做出确定性承诺。
- **《个人信息保护法》**：处理客户个人信息须取得授权，遵循最小必要原则，做好数据安全保障。
- **《互联网保险业务监管办法》**：互联网保险业务须在合规框架下开展，AI 辅助工具不得替代专业核保和理赔判断。

### 1.2 AI 合规核心原则

本系统在设计之初即确立以下三大 AI 合规原则：

1. **对客先审后发**：AI 生成的话术在发送给客户之前，必须经过合规检查引擎的自动审查。任何未经合规检查的内容不得对外发送。代理人是最终的内容责任人，AI 仅为辅助工具。
2. **AI 仅辅助，不替代**：AI 的定位是销售辅助工具，其输出仅供参考和参考话术建议。系统不得替代代理人做出任何销售决策、核保结论或理赔判断。所有最终决策权归属具有执业资格的保险代理人。
3. **高风险人工确认**：涉及客户健康信息解读、产品收益分析、核保结论等高风险场景，系统必须强制要求人工确认或介入，不能仅凭 AI 自动输出结论。

## 2. 合规检查规则

### 2.1 八大违规类型

合规检查引擎内置以下八大违规类型检测规则，覆盖保险销售场景中的常见合规风险：

| 规则类型 | 说明 | 风险等级 | 检查方式 |
|----------|------|---------|----------|
| 收益承诺 | 承诺具体收益率、回报金额或投资回报，如"保证年化收益 5%" | RED | 关键词+模式匹配 |
| 绝对化表达 | 使用"肯定""一定""绝对""100%""稳赚不赔"等绝对化用语 | RED/YELLOW | 关键词 |
| 虚假比较 | 与竞品进行不当比较、贬低竞品或使用未经证实的数据进行对比 | RED | 关键词+AI判断 |
| 夸大保障 | 夸大保障范围、保险金额或理赔条件，超出产品条款实际约定 | YELLOW | 关键词 |
| 不当核保结论 | AI 自行给出核保结论，如"您这个情况可以标准体承保" | RED | 规则匹配 |
| 不当理赔承诺 | 承诺理赔结果或理赔时效，如"这个病一定能理赔" | RED | 关键词 |
| 诱导销售 | 使用恐吓、焦虑、紧迫感等话术进行诱导性销售 | RED/YELLOW | 关键词+AI判断 |
| 敏感医疗结论 | AI 给出医疗诊断或健康评估结论，如"这个指标偏高说明有肝病" | RED | 规则匹配 |

### 2.2 规则详细说明

#### 2.2.1 收益承诺（RED）

保险产品（尤其是分红险、万能险、投连险）的收益受多种因素影响，不得以任何形式承诺确定性收益。检查规则包括但不限于：

- "保证收益"、"保本保息"、"稳赚不赔"
- "年化收益 XX%"、"每月固定收益"
- "零风险"、"无风险投资"
- 任何数值化的收益率承诺（如"年化 5%"、"收益率不低于 3%"）

#### 2.2.2 绝对化表达（RED/YELLOW）

绝对化用语违反《广告法》和保险监管要求。根据用语的严重程度分为两个级别：

- **RED 级别**："一定"、"绝对"、"100%"、"肯定"、"毫无风险"
- **YELLOW 级别**："最好"、"最优"、"第一"、"首选"

#### 2.2.3 虚假比较（RED）

禁止在话术中直接贬低竞品或使用未经证实的对比数据：

- "XX 公司的产品不如我们"
- "比其他公司便宜 30%"（无依据）
- "市场上没有比这更好的产品了"

系统需同时使用关键词匹配和 AI 语义判断来识别此类违规。

#### 2.2.4 夸大保障（YELLOW）

话术中不应夸大产品的保障能力：

- "什么病都能保"、"全部报销"
- "保额没有上限"、"无限赔付"

此类表述可能误导客户对产品责任的理解。

#### 2.2.5 不当核保结论（RED）

核保是保险公司专属职能，AI 不得代替核保人员做出任何核保判断：

- "您的情况可以标准体承保"、"这个体检结果不影响投保"
- "加费 10% 就能保"、"这个病需要除外承保"

系统必须严格拦截此类内容，并提示代理人联系专业核保人员。

#### 2.2.6 不当理赔承诺（RED）

理赔结论必须由理赔部门根据实际材料审核确定：

- "这个病一定可以理赔"、"只要住院就能赔"
- "三天内理赔款到账"（超出实际承诺）

#### 2.2.7 诱导销售（RED/YELLOW）

禁止使用恐吓、焦虑或制造紧迫感的方式诱导客户：

- **RED 级别**："不买以后就买不到了"、"再不买就来不及了"、"不买保险出了事没人管"
- **YELLOW 级别**："现在买最划算"、"活动马上结束"、"名额有限"

#### 2.2.8 敏感医疗结论（RED）

AI 不是医疗诊断工具，不得对客户的健康状况做出任何医学结论：

- "这个指标偏高说明有肝病"
- "您这个症状可能是 XX 病"
- "建议您吃 XX 药"、"需要做 XX 手术"

所有涉及客户健康信息的分析，只能引用客户提供的资料原文，并明确标注"仅供参考，不构成医学诊断"。

## 3. 合规检查流程

### 3.1 标准检查流程

```
话术生成请求 → AI 生成话术 → 合规检查引擎自动扫描
                                     ↓
                        ┌────────────────────────────┐
                        │   逐条匹配八大违规规则        │
                        │   输出：GREEN / YELLOW / RED  │
                        └────────────────────────────┘
                                     ↓
                        ┌─── GREEN ──→ 直接展示给代理人，可发送
                        │
                        ├─── YELLOW ─→ 展示话术 + 合规建议，建议修改后发送
                        │
                        └─── RED ───→ 禁止发送，显示违规原因，要求修改
```

### 3.2 检查结果处理

- **GREEN（可用）**：话术通过所有合规规则检查，代理人可以直接使用或复制发送。系统在界面上标记为绿色通过状态。
- **YELLOW（建议修改）**：话术命中了 YELLOW 级别规则，系统会高亮标注风险点并给出修改建议。代理人可以选择忽略（记录留痕）或修改后重新检查。
- **RED（禁止发送）**：话术命中了 RED 级别规则，系统**强制禁止**该话术发送给客户。界面显示明确的违规类型和原因说明，代理人必须修改话术直到通过检查或放弃使用。

### 3.3 合规检查时序

合规检查是同步阻塞操作，在话术生成后、展示给代理人前完成。检查延迟目标：< 200ms。对于 RED 结果，系统应同时提供修改建议，帮助代理人快速调整话术内容。

## 4. 合规审核工作流

### 4.1 规则管理

合规管理员可以通过管理后台对话术合规规则进行完整的管理操作：

- **查看规则列表**：按规则类型、风险等级、状态筛选
- **创建规则**：配置规则名称、类型、关键词列表、风险等级、正则表达式模式
- **编辑规则**：修改规则参数，支持版本对比
- **启用/禁用规则**：灵活控制规则的生效状态，禁用后该规则不参与检查
- **删除规则**：软删除，保留历史记录

每条规则包含以下字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 规则唯一标识 |
| name | String | 规则名称 |
| type | Enum | 八大违规类型之一 |
| risk_level | Enum | RED / YELLOW |
| keywords | List[String] | 触发关键词列表 |
| pattern | String (可选) | 正则表达式模式 |
| description | String | 规则说明 |
| suggestion | String (可选) | 触发时的修改建议 |
| is_active | Boolean | 是否启用 |
| created_at / updated_at | DateTime | 时间戳 |

### 4.2 话术审核

合规管理员可以查看和处理系统中的合规事件：

- **查看 RED/YELLOW 记录**：按时间范围、代理人、规则类型、客户等维度筛选
- **查看话术详情**：完整的 AI 生成话术、命中规则、命中关键词高亮标注
- **人工审核**：对 YELLOW 话术进行人工复核，判断是否需要升级处理
- **处置操作**：
  - 标记为误报（优化规则）
  - 确认违规（通知代理人，记录合规事件）
  - 加入规则学习库（优化规则引擎）

### 4.3 合规报表

系统提供多维度合规数据报表，支持合规管理员和管理层了解整体合规状况：

- **拦截率趋势**：按日/周/月统计 RED 拦截率变化趋势
- **违规类型分布**：八大违规类型的命中占比（饼图/柱状图）
- **代理人合规排行**：各代理人的话术合规率排名
- **规则命中热力图**：高频触发规则及关键词
- **合规事件处理效率**：RED/YELLOW 事件的平均处理时间

## 5. 审计日志

### 5.1 日志记录范围

系统对以下所有关键动作进行完整的审计日志记录：

- **用户行为**：谁（agent_id/username）、什么时候（timestamp）、执行了什么操作（action）
- **数据访问**：访问了什么客户数据（customer_id）、查询了什么产品信息（product_id）
- **AI 交互**：问了什么问题（query）、AI 回答了什么（response）、依据是什么（sources/knowledge_ids）
- **合规事件**：是否命中风险规则（risk_level）、命中了哪条规则（rule_id）、是否修改后通过
- **话术操作**：生成、复制、发送（如果集成发送功能）

### 5.2 日志字段结构

```json
{
  "timestamp": "2026-08-13T10:30:00.000Z",
  "user_id": "agent-uuid",
  "action": "ai_chat",
  "resource_type": "conversation",
  "resource_id": "conv-uuid",
  "details": {
    "query": "客户有高血压，能买重疾险吗",
    "response_summary": "关于高血压投保重疾险的参考话术...",
    "compliance_result": "YELLOW",
    "matched_rules": ["sensitive_medical_conclusion"],
    "knowledge_sources": ["kb-001", "kb-003"]
  },
  "ip_address": "192.168.1.100",
  "user_agent": "Mozilla/5.0..."
}
```

### 5.3 日志安全要求

- 审计日志**不可由普通用户删除或修改**，仅系统管理员有归档权限
- 日志中涉及客户敏感信息（手机号、身份证号等）必须**脱敏存储**
- 日志保留周期：至少 180 天（可配置），超期自动归档
- 所有合规 RED 事件必须在 24 小时内被合规管理员审查

## 6. 合规风险分级

### 6.1 三级风险定义

| 等级 | 标识 | 含义 | 系统行为 |
|------|------|------|----------|
| GREEN | 🟢 | 话术通过所有合规检查，无风险 | 正常展示，可复制、可发送 |
| YELLOW | 🟡 | 话术存在潜在合规风险，建议修改 | 展示话术 + 风险提示 + 修改建议，代理人可选择忽略（留痕）|
| RED | 🔴 | 话术存在严重合规问题，禁止对外发送 | 禁止发送，强制要求修改，记录合规事件 |

### 6.2 多规则命中处理

当一条话术同时命中多条规则时：

- 取**最高风险等级**作为最终结果（RED > YELLOW > GREEN）
- 展示所有命中的规则及对应的风险提示
- 如果同时命中 RED 和 YELLOW 规则，最终结果为 RED
- 审计日志中记录所有命中的规则 ID

### 6.3 免责与责任归属

系统在以下位置明确标注免责声明：

- AI 对话界面顶部："AI 生成内容仅供参考，不构成销售建议或产品承诺。请以保险合同条款为准。"
- 话术生成结果下方："此话术已通过合规检查，但最终内容责任由代理人承担。"
- 客户画像分析页面："健康信息分析仅供参考，不构成医学诊断。"

## 7. Demo/Mock 标记

### 7.1 当前实现说明

当前 Demo 版本的合规检查引擎采用**关键词匹配 + 正则表达式**的方式实现，具备以下特点：

- 覆盖八大违规类型的核心关键词
- 支持 RED/YELLOW 两级风险分级
- 支持规则的动态启用/禁用
- 检查延迟在 50ms 以内

### 7.2 生产环境升级方向

真实的保险销售场景中，违规话术的表述方式多样且隐蔽，仅靠关键词匹配难以覆盖所有情况。生产环境建议的升级方向包括：

- **NLP 语义分析**：使用预训练的中文 NLP 模型进行语义级别的合规判断，识别关键词无法覆盖的隐性违规表述
- **上下文感知**：结合对话上下文判断话术的合规性，避免孤立句子的误判
- **AI 辅助合规审查**：使用专门训练的合规审查模型对高风险话术进行二次判断
- **持续学习**：基于人工审核的反馈数据持续优化合规规则和模型
- **行业规则库**：接入监管机构发布的最新合规规则和案例，保持规则的时效性

### 7.3 合规规则迭代策略

- **初始版本**：基于产品需求和行业经验的规则集（当前 Demo）
- **运营期**：每周分析合规日志，发现新规则需求，优化现有规则
- **成熟期**：建立规则评审机制，任何规则变更需经合规团队审批
- **持续优化**：基于误报率和漏报率数据，调整规则灵敏度和阈值

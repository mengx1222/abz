## 1. 流程概述

### 1.1 设计原则

安诊保 AI 副驾的用户流程设计遵循以下核心原则：

| 原则 | 说明 |
|------|------|
| **模块独立可用** | 每个功能模块（产品专家、客户360、话术生成、AI陪练、社区、成长）均可独立使用，代理人不必按固定顺序操作。任意模块的入口均可从工作台或侧边栏直达 |
| **环节间数据流转** | 各模块之间通过上下文传递实现无缝衔接。例如，产品专家的问答结果可一键转为话术、客户详情页可直接生成针对该客户的话术、陪练成绩自动回写到成长体系 |
| **AI 始终在线** | AI 不是独立模块，而是渗透在每个业务环节的辅助能力。在产品问答中提供引用溯源、在客户管理中提供画像洞察、在话术中提供合规检查、在陪练中提供评分反馈 |
| **合规优先** | 所有 AI 输出（话术、回答、社区内容）均经过合规引擎校验，确保内容符合监管要求。合规检查贯穿内容生成、审核、发布的全生命周期 |
| **渐进式引导** | 首次登录用户提供引导流程，日常使用中通过 AI 建议和智能推荐降低认知负担，让用户自然形成使用习惯 |

### 1.2 主要用户旅程

本产品存在以下几条主要用户旅程，覆盖不同角色和场景：

| 旅程编号 | 旅程名称 | 主要角色 | 核心路径 |
|----------|----------|----------|----------|
| J1 | **销售闭环旅程** | 代理人 | 登录 → 工作台 → AI产品专家（了解产品） → 客户360（分析客户） → AI话术（生成话术） → AI陪练（模拟练习） → 真实销售 → 记录结果 → AI复盘 → 社区分享 |
| J2 | **日常问答旅程** | 代理人 | 登录 → AI产品专家 → 输入问题 → 查看引用 → 追问/转话术 → 完成 |
| J3 | **客户管理旅程** | 代理人 | 登录 → 客户360 → 筛选客户 → 查看AI画像 → 生成话术 → 记录跟进 → 状态更新 |
| J4 | **团队管理旅程** | 团队主管 | 登录 → 团队工作台 → 查看数据 → 查看成员使用情况 → 查看客户分配 → 分析报表 |
| J5 | **知识管理旅程** | 知识库管理员 | 登录 → 知识库管理 → 上传文档 → 解析预览 → Chunk管理 → 提交审核 → 合规通过 → 发布 |
| J6 | **合规审核旅程** | 合规人员 | 登录 → 合规中心 → 查看待审内容 → 审核话术 → 查看RED级别 → 处置违规内容 → 生成报表 |
| J7 | **全局管控旅程** | 总部管理员 | 登录 → 数据看板 → 用户管理 → 系统配置 → 审计日志 |

### 2.2 各步骤详细说明

#### Step 1: 登录

| 维度 | 说明 |
|------|------|
| **触发条件** | 用户打开应用，未持有有效 JWT Token |
| **用户操作** | 输入手机号 → 点击「获取验证码」 → 输入短信验证码 → 点击「登录」 |
| **系统响应** | ① 校验验证码有效性（Redis 查询，60秒过期） ② 识别用户角色（AGENT / TEAM_LEADER / ADMIN 等） ③ 生成 JWT Token（含 role、team_id、permissions） ④ 加载用户权限列表和团队数据 ⑤ 重定向至对应工作台 |
| **数据流向** | 手机号 + 验证码 → AuthService.verify() → User 表查询角色 → JWT 签发 → 前端存储 Token → 后续请求携带 Authorization Header |
| **异常处理** | ① 验证码错误：清空输入框，提示「验证码错误，请重新输入」 ② 验证码过期：提示「验证码已过期，请重新获取」 ③ 手机号未注册：提示「该手机号未注册，请联系管理员开通账号」 ④ 账号被禁用：提示「账号已被禁用，请联系管理员」 ⑤ 网络异常：展示骨架屏，3秒后重试，仍失败显示「网络异常，请检查网络后重试」 |

#### Step 2: 工作台

| 维度 | 说明 |
|------|------|
| **触发条件** | 登录成功后自动跳转，或点击 Logo / 侧边栏「工作台」|
| **用户操作** | 浏览今日数据卡片 → 查看AI建议列表 → 点击快捷操作入口 → 查看最近使用记录 |
| **系统响应** | ① 加载今日待跟进客户数、待回复客户数、今日陪练任务数、知识更新数 ② AI引擎基于用户历史数据生成个性化建议（优先级排序） ③ 拉取最近7天的问答、话术、陪练记录 ④ 展示个性化问候语（根据时间段：早上好/下午好/晚上好） |
| **数据流向** | DashboardService.get_summary() → 聚合 Customer/Script/Training/Knowledge 数据 → AI Engine 生成建议 → 返回聚合数据 |
| **异常处理** | ① AI建议生成超时（>5秒）：先展示基础数据，AI建议区域显示加载态，完成后刷新 ② 无待跟进客户：卡片显示「暂无待跟进客户，去客户库看看」引导 ③ 新用户无历史数据：展示引导流程（Feature Tour） |

#### Step 3: AI产品专家

| 维度 | 说明 |
|------|------|
| **触发条件** | 点击侧边栏「AI产品专家」或工作台快捷入口「问产品」或全局搜索无果后引导 |
| **用户操作** | 选择产品范围（可选） → 输入问题 → 等待流式回答 → 查看引用来源 → 点击追问/反馈/转话术 |
| **系统响应** | ① 将用户问题通过 Embedding 模型转向量 ② 在知识库向量索引中检索 Top-K 相关文档片段 ③ 构建 Prompt（系统指令 + 检索上下文 + 用户问题） ④ 调用 LLM 流式生成回答 ⑤ 实时返回 SSE 事件流 ⑥ 回答完成后展示引用来源列表 |
| **数据流向** | 用户问题 → AIService → AIGateway.embed() → VectorStore.search() → PromptBuilder.build() → AIGateway.chat(stream=True) → SSE 推送 → 前端 Markdown 渲染 |
| **异常处理** | ① RAG 检索无结果：返回「未找到相关知识，已转交专家团队，预计24小时内回复」并记录 gap ② LLM 超时：显示「回答生成超时，请重试」并保留问题 ③ 流式中断：已生成内容保留，提示「回答中断，点击继续」 ④ AI 服务不可用：降级为关键词匹配 + 常见问题推荐 |

#### Step 4: 客户360

| 维度 | 说明 |
|------|------|
| **触发条件** | 点击侧边栏「客户360」或工作台AI建议中点击客户名 |
| **用户操作** | 在客户列表中筛选/搜索 → 点击进入客户详情 → 查看AI画像 → 查看跟进时间线 → 点击「快速生成话术」或「开始模拟陪练」 → 添加跟进记录 |
| **系统响应** | ① 加载客户列表（支持分页、排序、多维度筛选） ② 进入详情页后，AI引擎实时生成客户画像摘要 ③ 展示跟进时间线（按时间倒序） ④ 右侧AI面板展示沟通策略建议和产品推荐理由 ⑤ 关联展示该客户的问答记录、话术记录、陪练记录 |
| **数据流向** | CustomerService.list() / .get_detail() → AIService.analyze_customer() → 聚合跟进记录/话术/陪练数据 → 返回客户全景视图 |
| **异常处理** | ① 客户数据为空：引导「去录入第一个客户」 ② AI画像生成失败：展示基础信息，AI区域降级为「暂无分析数据」 ③ 权限不足：提示「您无权查看该客户信息」（跨团队访问时） |

#### Step 5: AI话术

| 维度 | 说明 |
|------|------|
| **触发条件** | 点击侧边栏「AI话术」或客户详情页「快速生成话术」或产品问答页「转话术」 |
| **用户操作** | 选择目标客户（或新建） → 设定沟通场景 → 选择风格 → 点击「生成话术」 → 等待生成 → 查看合规检查结果 → 编辑微调 → 复制/分享 |
| **系统响应** | ① 加载客户画像和产品知识作为上下文 ② LLM 基于上下文生成多风格话术（专业严谨/亲和温暖/简洁高效） ③ 话术自动送入合规引擎检查 ④ 返回话术内容 + 合规检查结果（GREEN/YELLOW/RED） ⑤ 编辑保存后进入话术库 |
| **数据流向** | 客户ID + 场景 + 风格 → ScriptService.generate() → AIService + ComplianceService → Script 表存储 → 返回结果 |
| **异常处理** | ① 合规检查 RED：话术标记为「待修改」，展示违规原因，禁止复制/分享 ② 合规检查 YELLOW：话术标记为「需注意」，展示风险点，允许复制但显示警告 ③ 生成失败：提示「话术生成失败，请重试」并保留已填参数 |

#### Step 6: AI陪练

| 维度 | 说明 |
|------|------|
| **触发条件** | 点击侧边栏「AI陪练」或客户详情页「开始模拟陪练」或工作台「今日陪练任务」 |
| **用户操作** | 选择陪练场景（首次面谈/异议处理/促成等） → 选择难度（初级/中级/高级） → 开始对话 → 多轮模拟 → 结束训练 → 查看评分报告 → 查看改进建议 |
| **系统响应** | ① 加载陪练场景配置（角色设定、对话目标、评分维度） ② AI扮演客户角色进行多轮对话 ③ 实时评估用户每一轮回复（内容准确性、沟通技巧、合规性） ④ 训练结束后生成综合评分报告和改进建议 ⑤ 评分数据写入成长体系 |
| **数据流向** | 场景ID + 难度 → TrainingService.start() → AIService.roleplay() → TrainingService.evaluate() → GrowthService.update_scores() → 返回报告 |
| **异常处理** | ① 对话中AI无响应（>10秒）：提示「对方正在思考...」，15秒后自动重试 ② 用户中途退出：自动保存当前进度，下次可继续 ③ 评分生成失败：保留对话记录，评分区域显示「评估生成中，完成后通知您」 |

#### Step 7: 真实销售

| 维度 | 说明 |
|------|------|
| **触发条件** | 话术准备完毕后，代理人通过线下渠道（电话/面谈/微信）与客户沟通 |
| **用户操作** | 沟通完成后，在系统中记录：沟通方式、沟通结果（成交/拒绝/跟进中）、关键信息、客户反馈 |
| **系统响应** | ① 保存跟进记录到客户时间线 ② 更新客户阶段状态 ③ 若成交：触发成功数据更新到工作台和成长体系 ④ 若拒绝：AI分析拒绝原因并推荐后续策略 ⑤ 若跟进中：设置下次跟进提醒 |
| **数据流向** | 跟进记录表单 → CustomerService.add_followup() → 客户状态机流转 → DashboardService / GrowthService 数据更新 |
| **异常处理** | ① 必填字段缺失：表单校验提示 ② 客户状态已变更：提示「该客户状态已被更新，请刷新后操作」 |

#### Step 8: AI复盘

| 维度 | 说明 |
|------|------|
| **触发条件** | 真实销售记录提交后，系统自动触发或在「我的成长」中手动发起 |
| **用户操作** | 查看AI生成的复盘报告 → 查看差距分析 → 查看改进建议 → 点击「去训练」跳转陪练 |
| **系统响应** | ① AI基于跟进记录、使用的话术、陪练历史进行综合分析 ② 生成差距分析（与优秀话术对比） ③ 识别知识薄弱点 ④ 推荐针对性训练场景 ⑤ 更新能力画像 |
| **数据流向** | 跟进记录 + 话术 + 陪练 → GrowthService.review() → AIService.analyze() → 能力画像更新 + 训练推荐生成 |
| **异常处理** | ① 数据不足无法复盘：提示「至少完成3次销售记录后可使用AI复盘功能」 ② 复盘报告生成超时：异步生成，完成后推送通知 |

#### Step 9: AI社区

| 维度 | 说明 |
|------|------|
| **触发条件** | 点击侧边栏「AI社区」或复盘后引导分享 |
| **用户操作** | 浏览社区首页 → 阅读精华帖 → 提问/回答 → 分享成功案例 → 收藏有价值的内容 |
| **系统响应** | ① 加载社区内容流（推荐 + 最新 + 精华） ② AI对发帖内容进行自动审核 ③ 高质量回答被标记为「精华」 ④ 优秀案例可被提炼为知识库内容 |
| **数据流向** | CommunityService.list() / .create() / .reply() → ComplianceService.auto_check() → 社区内容表更新 → 精华内容 → KnowledgeService.ingest() |
| **异常处理** | ① 发帖审核不通过：提示「内容审核未通过，请修改后重新提交」并说明原因 ② 社区内容为空（新团队）：展示引导帖和常见问题 |

#### Step 10: 成长

| 维度 | 说明 |
|------|------|
| **触发条件** | 点击侧边栏「我的成长」或工作台成绩入口 |
| **用户操作** | 查看AI能力画像（雷达图） → 查看成绩趋势曲线 → 查看团队排名 → 点击推荐训练 |

| **数据流向** | GrowthService.get_profile() → 聚合 Training/Script/Community 数据 → AI 能力评估 → 可视化数据 → 推荐训练列表 |
| **异常处理** | ① 新用户无数据：展示「完成首次陪练后解锁成长画像」引导 ② 数据计算超时：展示缓存数据并标注更新时间 |

**详细说明**：

- **Demo 模式说明**：MVP 阶段采用手机号 + 短信验证码登录方式，不涉及密码管理。验证码有效期 60 秒，每日每手机号最多发送 5 次。系统通过手机号自动识别用户角色，无需手动选择。
- **首次登录**：首次登录的用户会看到一个简短的引导流程（3-4步），介绍工作台、AI产品专家、客户360 等核心功能位置。
- **Token 管理**：JWT Token 有效期 24 小时，Refresh Token 有效期 7 天。Token 过期后前端自动使用 Refresh Token 刷新，对用户无感知。

### 6.1 知识文档状态机

```
                         ┌──────────────────────────────────────┐
                         │                                      │
                         ▼                                      │
  ┌────────┐    ┌────────┐    ┌────────┐    ┌──────────┐    ┌────────┐
  │  上传  │───→│  解析  │───→│  草稿  │───→│  审核中  │───→│ 已发布 │
  │ UPLOAD │    │ PARSING│    │ DRAFT  │    │ REVIEWING│    │PUBLISHED│
  └────────┘    └───┬────┘    └───┬────┘    └────┬─────┘    └───┬────┘
                    │             │              │               │
                    │ 解析失败     │              │ 审核驳回      │ 发布后按
                    ▼             │              ▼               │ 生效日期
               ┌────────┐        │         ┌────────┐          │ 自动切换
               │ 解析   │        │         │ 草稿   │          ▼
               │ 失败   │        │         │ (退回) │    ┌──────────┐
               │ FAILED │        │         └────────┘    │  生效中  │
               └───┬────┘        │                      │ EFFECTIVE │
                   │             │                      └─────┬────┘
                   │ 重新上传     │                            │
                   └─────────────┘                     到期/新版发布
                                                            │
                                                            ▼
                                                      ┌──────────┐
                                                      │  失效   │
                                                      │ EXPIRED  │
                                                      └──────────┘

状态说明:
  UPLOAD    → 文件已上传至服务器，等待解析
  PARSING   → 系统正在解析文档（PDF/DOCX → 文本 → Chunk）
  DRAFT     → 解析完成，管理员可编辑Chunk和Metadata
  REVIEWING → 已提交审核，等待合规人员审核
  PUBLISHED → 审核通过并发布，内容已写入向量索引
  EFFECTIVE → 到达生效日期，正式对用户可见（产品专家可检索到）
  EXPIRED   → 到达失效日期或被新版替代，不再参与检索

注意: PUBLISHED → EFFECTIVE 之间可能有时间差（如提前发布但8月1日才生效）
```

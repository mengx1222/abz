     1→# 数据库设计文档 — 安诊保 AI 副驾
     2→
     3→## 1. 设计概述
     4→
     5→### 1.1 数据库选型
     6→
     7→| 组件 | 技术选型 | 版本 | 用途 |
     8→|------|---------|------|------|
     9→| 主数据库 | PostgreSQL | 16+ | 关系型数据持久化存储 |
    10→| 向量扩展 | pgvector | 0.7+ | 文档向量检索（RAG） |
    11→| 缓存 | Redis | 7.0+ | 会话缓存、热数据、限流计数 |
    12→| 迁移工具 | Alembic | — | 数据库版本管理 |
    13→
    14→### 1.2 设计原则
    15→
    16→1. **三范式为主**：核心业务表严格遵循第三范式，减少数据冗余与更新异常。
    17→2. **JSONB 补充**：仅在以下场景使用 JSONB——
    18→   - 扩展元数据（metadata），如文档附加属性、AI 分析结果等非结构化信息；
    19→   - 标签数组（tags），轻量级多值属性；
    20→   - 配置项（scoring_rules、keywords），结构不固定或频繁变更的集合数据。
    21→3. **软删除**：所有表统一采用 `is_deleted + deleted_at` 字段，不执行物理删除，保留审计追溯能力。
    22→4. **审计字段**：每张表均包含 `created_at`、`updated_at`、`created_by`、`updated_by` 四个审计字段，确保数据变更可追踪。
    23→5. **字段级权限**：敏感字段（客户手机号、身份证号等）通过 PostgreSQL 行级安全策略（RLS）+ 应用层加密实现访问控制。
    24→6. **完整审计链**：所有业务关键操作通过 `audit_logs` 表记录，形成完整操作链条。
    25→
    26→### 1.3 命名规范
    27→
    28→| 类别 | 规范 | 示例 |
    29→|------|------|------|
    30→| 表名 | snake_case，复数形式 | `users`、`customer_tags`、`document_chunks` |
    31→| 字段名 | snake_case | `created_at`、`intent_score` |
    32→| 主键 | `id`，统一 UUID | — |
    33→| 外键 | `{关联表单数}_id` | `user_id`、`organization_id` |
    34→| 布尔字段 | `is_xxx_` 前缀 | `is_deleted`、`is_active` |
    35→| 关联表（中间表） | `{表1}_{表2}` | `role_permissions`、`community_likes` |
    36→| 索引 | `idx_{表名}_{字段名}` | `idx_customers_owner_id` |
    37→| 唯一约束 | `uq_{表名}_{字段名}` | `uq_users_phone` |
    38→| 检查约束 | `ck_{表名}_{描述}` | `ck_training_scores_score_range` |

    42→## 2. 公共字段规范
    43→
    44→所有业务表（除中间表外）均包含以下公共字段：
    45→
    46→| 字段 | 类型 | 约束 | 说明 |
    47→|------|------|------|------|
    48→| id | UUID | PK, DEFAULT gen_random_uuid() | 主键，全局唯一标识 |
    49→| created_at | TIMESTAMPTZ | NOT NULL, DEFAULT now() | 创建时间（带时区） |
    50→| updated_at | TIMESTAMPTZ | NOT NULL, DEFAULT now() | 最后更新时间 |
    51→| created_by | UUID | FK → users(id), NOT NULL | 创建人 |
    52→| updated_by | UUID | FK → users(id), NOT NULL | 最后更新人 |
    53→| is_deleted | BOOLEAN | NOT NULL, DEFAULT false | 软删除标记 |
    54→| deleted_at | TIMESTAMPTZ | | 删除时间，NULL 表示未删除 |
    55→
    56→**更新触发器**：所有表均启用 `ON UPDATE` 触发器，自动将 `updated_at` 设为 `now()`。
    57→
    58→**中间表**（如 `role_permissions`、`community_likes`）仅包含 `id`、`created_at`，不含完整审计字段。

   179→#### 4.1.1 users（用户表）
   180→
   181→**用途说明**：存储系统所有用户信息，包括保险代理人、主管、管理员等。
   182→
   183→| 字段 | 类型 | 约束 | 说明 |
   184→|------|------|------|------|
   185→| id | UUID | PK | 主键 |
   186→| phone | VARCHAR(20) | UNIQUE, NOT NULL | 手机号（登录账号） |
   187→| password_hash | VARCHAR(255) | NOT NULL | 密码哈希（bcrypt） |
   188→| name | VARCHAR(100) | NOT NULL | 姓名 |
   189→| avatar_url | VARCHAR(500) | | 头像URL |
   190→| role_id | UUID | FK → roles(id) | 角色 |
   191→| organization_id | UUID | FK → organizations(id) | 所属机构 |
   192→| team_id | UUID | FK → users(id), NULLABLE | 所属团队（主管用户ID） |
   193→| status | VARCHAR(20) | NOT NULL, DEFAULT 'active' | 状态：active / disabled / locked |
   194→| last_login_at | TIMESTAMPTZ | | 最后登录时间 |
   195→| demo_mode | BOOLEAN | NOT NULL, DEFAULT false | 是否 Demo 用户 |
   196→| employee_id | VARCHAR(50) | | 工号 |
   197→| email | VARCHAR(200) | | 邮箱 |
   198→| department | VARCHAR(100) | | 部门 |
   199→| title | VARCHAR(100) | | 职位 |
   200→| metadata | JSONB | DEFAULT '{}' | 扩展信息 |
   201→
   202→**索引设计**：
   203→
   204→| 索引名 | 类型 | 字段 | 说明 |
   205→|--------|------|------|------|
   206→| uq_users_phone | UNIQUE | phone | 手机号唯一 |
   207→| idx_users_role_id | B-Tree | role_id | 角色查询 |
   208→| idx_users_organization_id | B-Tree | organization_id | 机构查询 |
   209→| idx_users_team_id | B-Tree | team_id | 团队查询 |
   210→| idx_users_status | B-Tree | status | 状态筛选 |
   211→| idx_users_demo_mode | B-Tree | demo_mode | Demo用户筛选 |
   212→
   213→**关系**：
   214→- `role_id` → `roles(id)`
   215→- `organization_id` → `organizations(id)`
   216→- `team_id` → `users(id)`（自引用，指向团队主管）

   245→#### 4.1.3 permissions（权限表）
   246→
   247→**用途说明**：定义系统细粒度权限项，采用「资源 + 操作」模式。

   253→| name | VARCHAR(100) | NOT NULL | 权限名称 |
   254→| resource | VARCHAR(50) | NOT NULL | 资源类型：customer / product / knowledge / ai / training / community / compliance / system |
   255→| action | VARCHAR(50) | NOT NULL | 操作类型：view / create / edit / delete / export / approve |
   256→| description | TEXT | | 权限描述 |

   258→**索引设计**：
   259→
   260→| 索引名 | 类型 | 字段 | 说明 |
   261→|--------|------|------|------|
   262→| uq_permissions_code | UNIQUE | code | 权限代码唯一 |
   263→| idx_permissions_resource | B-Tree | resource | 资源类型查询 |
   264→| idx_permissions_resource_action | B-Tree | (resource, action) | 资源+操作联合查询 |
   265→
   266→**关系**：
   267→- 通过 `role_permissions` 中间表关联 `roles`

   304→| path | VARCHAR(1000) | | 层级路径（如 `/hq/branch1/team1/`），加速树查询 |
   305→| status | VARCHAR(20) | NOT NULL, DEFAULT 'active' | 状态：active / disabled |
   306→| contact_phone | VARCHAR(20) | | 联系电话 |
   307→| address | VARCHAR(500) | | 地址 |
   308→| metadata | JSONB | DEFAULT '{}' | 扩展信息 |

   315→| idx_organizations_parent_id | B-Tree | parent_id | 父级查询 |
   316→| idx_organizations_type | B-Tree | type | 类型筛选 |

   341→| phone_masked | VARCHAR(20) | | 脱敏手机号（如 138****5678） |

  1384→```

  1442→
  1443→### 5.3 缓存更新策略
  1444→
  1445→- **Cache Aside**：读时先查缓存，miss 后查 DB 并写入缓存；写时先更新 DB 再删除缓存
  1446→- **Write Through**：对高频更新的配置类数据使用
  1447→- **Cache Invalidation**：数据变更时通过事件机制主动清除相关缓存
  1448→- **TTL 兜底**：所有缓存设置 TTL，防止脏数据长期存在

  1452→## 6. 索引策略
  1453→
  1454→### 6.1 主键索引
  1455→
  1456→所有表的主键 `id`（UUID）自动创建 B-Tree 索引，由 PostgreSQL 主键约束隐式创建。
  1457→
  1458→### 6.2 外键索引
  1459→
  1460→所有外键字段均创建 B-Tree 索引，加速 JOIN 查询和级联操作：
  1461→
  1462→```sql
  1463→-- 外键索引命名规范
  1464→CREATE INDEX idx_{表名}_{外键字段} ON {表名}({外键字段});
  1465→```
  1466→
  1467→### 6.3 常用查询索引
  1468→
  1469→根据业务查询模式设计复合索引和条件索引：
  1470→
  1471→| 索引策略 | 适用场景 | 示例 |
  1472→|----------|---------|------|
  1473→| 单列 B-Tree | 状态筛选、类型筛选 | `idx_customers_stage` |
  1474→| 复合 B-Tree | 多条件联合查询 | `idx_customers_owner_stage` ON (owner_id, stage) |
  1475→| 排序索引 | 列表排序 | `idx_conversations_last_message` ON (user_id, last_message_at DESC) |
  1476→| 部分索引 | 带状态过滤的查询 | `WHERE status = 'active' AND is_deleted = false` |
  1477→| GIN 索引 | JSONB 内部字段检索 | `idx_customers_tags` ON tags USING GIN |
  1478→
  1479→### 6.4 pgvector 向量索引
  1480→
  1481→**向量字段**：`document_chunks.embedding`（vector(1536)）
  1482→
  1483→```sql
  1484→-- 方案一：IVFFlat（适用于 < 10,000 条切片）
  1485→CREATE INDEX idx_chunks_embedding_ivfflat
  1486→ON document_chunks
  1487→USING ivfflat (embedding vector_cosine_ops)
  1488→WITH (lists = 100);  -- lists ≈ sqrt(总行数)
  1489→
  1490→-- 方案二：HNSW（适用于 ≥ 10,000 条切片，推荐）
  1491→CREATE INDEX idx_chunks_embedding_hnsw
  1492→ON document_chunks
  1493→USING hnsw (embedding vector_cosine_ops)
  1494→WITH (m = 16, ef_construction = 64);
  1495→```
  1496→
  1497→**查询方式**：
  1498→
  1499→```sql
  1500→-- 余弦相似度检索（距离越小越相似）
  1501→SELECT dc.id, dc.content, dc.document_id,
  1502→       1 - (dc.embedding <=> $1::vector) AS similarity
  1503→FROM document_chunks dc
  1504→WHERE dc.is_deleted = false
  1505→ORDER BY dc.embedding <=> $1::vector
  1506→LIMIT 5;
  1507→```
  1508→
  1509→**索引选择建议**：
  1510→- 数据量 < 1 万：IVFFlat，构建快，查询精度高
  1511→- 数据量 1~50 万：HNSW（m=16, ef_construction=64），查询速度快
  1512→- 数据量 > 50 万：HNSW（m=32, ef_construction=100），增加精度
  1513→
  1514→### 6.5 部分索引策略
  1515→
  1516→针对高频查询中的状态过滤条件，使用部分索引减少索引大小、提升查询性能：
  1517→
  1518→```sql
  1519→-- 仅索引活跃客户
  1520→CREATE INDEX idx_customers_active
  1521→ON customers(owner_id)
  1522→WHERE is_deleted = false;
  1523→
  1524→-- 仅索引待跟进任务
  1525→CREATE INDEX idx_followups_pending
  1526→ON customer_followups(user_id, planned_at)
  1527→WHERE status = 'pending' AND is_deleted = false;
  1528→
  1529→-- 仅索引未读通知
  1530→CREATE INDEX idx_notifications_unread
  1531→ON notifications(user_id, created_at DESC)
  1532→WHERE is_read = false AND is_deleted = false;
  1533→
  1534→-- 仅索引活跃合规规则
  1535→CREATE INDEX idx_compliance_rules_active
  1536→ON compliance_rules(id)
  1537→WHERE is_active = true AND is_deleted = false;
  1538→```
  1539→
  1540→### 6.6 索引维护
  1541→
  1542→- **定期 VACUUM**：每周执行 `VACUUM ANALYZE`，更新统计信息
  1543→- **REINDEX**：每月对碎片化严重的索引执行 `REINDEX CONCURRENTLY`
  1544→- **监控**：通过 `pg_stat_user_indexes` 监控索引使用率，移除无用索引

  1548→## 7. 数据安全
  1549→
  1550→### 7.1 字段级加密
  1551→
  1552→对客户敏感信息在应用层进行 AES-256-GCM 加密后存储：
  1553→
  1554→| 表 | 字段 | 加密方式 | 说明 |
  1555→|----|------|---------|------|
  1556→| customers | phone | AES-256-GCM | 手机号加密，密文存储于 `phone` 字段 |
  1557→| customers | id_card | AES-256-GCM | 身份证号加密 |
  1558→| customer_interactions | content | AES-256-GCM（可选） | 沟通详细内容加密 |
  1559→| users | password_hash | bcrypt | 密码哈希（单向，非加密） |
  1560→
  1561→**加密实现要点**：
  1562→- 密钥通过 KMS（密钥管理服务）管理，不硬编码
  1563→- 每条记录使用唯一 IV（初始化向量）
  1564→- 加密后的密文以 Base64 编码存储
  1565→- 脱敏值（`phone_masked`、`id_card_masked`）单独存储，查询展示时无需解密
  1566→
  1567→### 7.2 脱敏策略
  1568→
  1569→| 数据类型 | 脱敏规则 | 示例 |
  1570→|---------|---------|------|
  1571→| 手机号 | 中间4位替换为 `****` | 138****5678 |
  1572→| 身份证号 | 保留前3后4位 | 110***********1234 |
  1573→| 姓名 | 保留姓氏，名替换为 `*` | 张** |
  1574→| 银行卡号 | 保留后4位 | ************5678 |
  1575→| 地址 | 保留省市，详细地址替换 | 北京市朝阳区*** |
  1576→
  1577→**脱敏时机**：
  1578→- **存储时**：写入 `phone_masked`、`id_card_masked` 字段
  1579→- **传输时**：API 响应中对敏感字段进行脱敏
  1580→- **展示时**：前端根据用户权限展示原值或脱敏值
  1581→
  1582→### 7.3 行级安全策略（RLS）
  1583→
  1584→PostgreSQL 原生 RLS 策略，实现数据隔离：
  1585→
  1586→```sql
  1587→-- 启用 RLS
  1588→ALTER TABLE customers ENABLE ROW LEVEL SECURITY;
  1589→
  1590→-- 代理人仅能查看自己的客户
  1591→CREATE POLICY customers_agent_access ON customers
  1592→  FOR SELECT
  1593→  USING (owner_id = current_setting('app.current_user_id')::uuid);
  1594→
  1595→-- 团队主管可查看团队成员的客户
  1596→CREATE POLICY customers_team_leader_access ON customers
  1597→  FOR SELECT
  1598→  USING (owner_id IN (
  1599→    SELECT id FROM users WHERE team_id = current_setting('app.current_user_id')::uuid
  1600→  ));
  1601→
  1602→-- 分公司管理员可查看本机构及下级的客户
  1603→CREATE POLICY customers_branch_admin_access ON customers
  1604→  FOR SELECT
  1605→  USING (owner_id IN (
  1606→    SELECT u.id FROM users u
  1607→    JOIN organizations o ON u.organization_id = o.id
  1608→    WHERE o.path LIKE (current_setting('app.current_org_path') || '%')
  1609→  ));
  1610→
  1611→-- 总部管理员查看所有
  1612→CREATE POLICY customers_hq_access ON customers
  1613→  FOR ALL
  1614→  USING (current_setting('app.current_role_code') = 'HQ_ADMIN');
  1615→```
  1616→
  1617→**RLS 应用范围**：
  1618→- `customers` — 客户数据隔离
  1619→- `customer_interactions` — 沟通记录隔离
  1620→- `customer_followups` — 跟进计划隔离
  1621→- `conversations` — AI 对话隔离
  1622→- `training_sessions` — 陪练记录隔离
  1623→
  1624→### 7.4 最小权限原则
  1625→
  1626→**数据库角色设计**：
  1627→
  1628→| 角色 | 权限 | 说明 |
  1629→|------|------|------|
  1630→| `app_superuser` | ALL | 应用超级用户，仅运维使用 |
  1631→| `app_readwrite` | SELECT, INSERT, UPDATE, DELETE | 应用读写用户（不可 DDL） |
  1632→| `app_readonly` | SELECT | 只读用户（报表、分析） |
  1633→| `app_migration` | ALL (schema) | 迁移用户（仅 Alembic 使用） |
  1634→
  1635→**连接安全**：
  1636→- 所有连接强制 SSL
  1637→- 密码认证 + 证书认证（生产环境）
  1638→- 连接池使用 PgBouncer，限制最大连接数

  1887→-- 自动更新 updated_at 字段的触发器函数
  1888→CREATE OR REPLACE FUNCTION update_updated_at_column()
  1889→RETURNS TRIGGER AS $$
  1890→BEGIN
  1891→    NEW.updated_at = now();
  1892→    RETURN NEW;
  1893→END;
  1894→$$ LANGUAGE plpgsql;

  1901→
  1902→-- 软删除触发器（可选，设置 deleted_at）
  1903→CREATE OR REPLACE FUNCTION set_deleted_at()
  1904→RETURNS TRIGGER AS $$
  1905→BEGIN
  1906→    IF NEW.is_deleted = true AND OLD.is_deleted = false THEN
  1907→        NEW.deleted_at = now();
  1908→    ELSIF NEW.is_deleted = false THEN
  1909→        NEW.deleted_at = NULL;
  1910→    END IF;
  1911→    RETURN NEW;
  1912→END;
  1913→$$ LANGUAGE plpgsql;
  1914→```

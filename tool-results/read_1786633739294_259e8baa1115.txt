     1→# 系统架构文档 — 安诊保 AI 副驾
     2→
     3→## 1. 架构概述
     4→
     5→安诊保 AI 副驾是一款面向保险代理人的智能销售助手工作台。系统通过 AI 驱动的产品问答、客户画像、话术生成、合规检查等核心能力，帮助保险代理人提升销售效率与专业水平。
     6→
     7→### 架构风格
     8→
     9→- **前后端分离**：前端（React SPA）与后端（FastAPI）通过 RESTful API + SSE 进行通信，职责清晰、独立部署。
    10→- **微服务化预留**：当前阶段采用单体架构（Modular Monolith），但在模块边界、数据访问层做了严格的解耦设计，未来可按业务域拆分为独立微服务。
    11→- **AI-Native 设计**：AI 能力不是附属功能，而是贯穿整个业务流程的核心基础设施。所有业务模块均可通过统一的 AI Gateway 调用大模型能力。
    12→
    13→### 架构原则
    14→
    15→| 原则       | 说明                                                                 |
    16→| ---------- | -------------------------------------------------------------------- |
    17→| **安全**   | JWT 认证 + RBAC 权限 + 数据脱敏 + 合规引擎 + Prompt Injection 防护 + 审计日志 |
    18→| **可维护** | 分层架构（Router → Service → Repository → Model）、统一错误处理、结构化日志     |
    19→| **可扩展** | AI Gateway 统一接口、Provider 可插拔、RAG Pipeline 可配置、水平扩展预留     |
    20→| **AI-Native** | AI 能力深度融入业务流程，而非外挂式集成                              |

   234→### 3.3 状态管理策略
   235→
   236→本系统采用**分层状态管理**策略，根据数据来源和生命周期选择最合适的管理方案：
   237→
   238→```
   239→┌─────────────────────────────────────────────────────────────┐
   240→│                      状态管理分层                             │
   241→├─────────────────────┬───────────────────────────────────────┤
   242→│  服务端状态          │  TanStack React Query                  │
   243→│  (Server State)     │  · 自动缓存与过期                      │
   244→│                     │  · 后台自动刷新                        │
   245→│                     │  · 乐观更新（Optimistic Update）         │
   246→│                     │  · 分页与无限滚动                       │
   247→│                     │  用途：API 数据（客户列表、知识库、对话历史）│
   248→├─────────────────────┼───────────────────────────────────────┤
   249→│  客户端全局状态       │  Zustand                               │
   250→│  (Client Global)    │  · 极简 API、无 Provider 包裹            │
   251→│                     │  · 支持 middleware（persist, devtools）  │
   252→│                     │  · 选择性订阅（避免不必要的重渲染）        │
   253→│                     │  用途：用户信息、UI 偏好、主题、侧边栏     │
   254→├─────────────────────┼───────────────────────────────────────┤
   255→│  表单状态            │  React Hook Form + Zod                 │
   256→│  (Form State)       │  · 非受控组件、高性能                    │
   257→│                     │  · 实时 Schema 校验                     │
   258→│                     │  用途：登录表单、客户信息录入、知识库上传   │
   259→├─────────────────────┼───────────────────────────────────────┤
   260→│  组件局部状态         │  useState / useReducer                 │
   261→│  (Component Local)  │  用途：弹窗开关、Tab 切换、临时 UI 状态   │
   262→└─────────────────────┴───────────────────────────────────────┘
   263→```

   446→### 4.3 分层架构
   447→
   448→```
   449→┌──────────────────────────────────────────────────────────────────────┐
   450→│                       分层架构（Layered Architecture）                │
   451→├──────────────────────────────────────────────────────────────────────┤
   452→│                                                                      │
   453→│  ┌────────────────────────────────────────────────────────────────┐  │
   454→│  │  Router 层 (api/v1/*.py)                                       │  │
   455→│  │  · 接收 HTTP 请求，参数校验（Pydantic）                           │  │
   456→│  │  · 调用 Service 层，返回标准化响应                                │  │
   457→│  │  · 不包含业务逻辑，仅做请求转发和响应格式化                          │  │
   458→│  │  · 职责：HTTP 语义 ↔ 应用语义的转换                               │  │
   459→│  └──────────────────────────┬─────────────────────────────────────┘  │
   460→│                             │ 调用                                  │
   461→│  ┌──────────────────────────▼─────────────────────────────────────┐  │
   462→│  │  Service 层 (services/*.py)                                    │  │
   463→│  │  · 核心业务逻辑编排                                              │  │
   464→│  │  · 事务管理（事务边界在此层定义）                                  │  │
   465→│  │  · 调用 Repository 层访问数据                                    │  │
   466→│  │  · 调用 AI Gateway / RAG Pipeline                              │  │
   467→│  │  · 调用 Compliance Engine 做合规检查                             │  │
   468→│  │  · 职责：业务规则实现、跨模块协调、外部服务编排                      │  │
   469→│  └──────────────────────────┬─────────────────────────────────────┘  │
   470→│                             │ 调用                                  │
   471→│  ┌──────────────────────────▼─────────────────────────────────────┐  │
   472→│  │  Repository 层 (repositories/*.py)                            │  │
   473→│  │  · 数据访问抽象（CRUD 操作封装）                                  │  │
   474→│  │  · 复杂查询构建（过滤、排序、分页、关联查询）                       │  │
   475→│  │  · 向量检索封装（pgvector 相似度搜索）                            │  │
   476→│  │  · 不包含业务逻辑，纯粹的数据库操作                                │  │
   477→│  │  · 职责：数据持久化、查询优化、数据访问解耦                         │  │
   478→│  └──────────────────────────┬─────────────────────────────────────┘  │
   479→│                             │ 操作                                  │
   480→│  ┌──────────────────────────▼─────────────────────────────────────┐  │

   491→### 4.4 中间件
   492→
   493→中间件按执行顺序排列，形成请求处理的「洋葱模型」：
   494→
   495→```
   496→HTTP Request
   497→    │
   498→    ▼
   499→┌─────────────────────────────────────────────────┐
   500→│  1. CORS Middleware                                │
   501→│     · 跨域策略配置（允许的 Origins、Methods、Headers）│
   502→│     · 仅在开发环境允许 *，生产环境严格白名单          │
   503→└──────────────────────┬──────────────────────────┘
   504→                       ▼
   505→┌─────────────────────────────────────────────────┐
   506→│  2. Request ID Middleware                          │
   507→│     · 为每个请求生成唯一 X-Request-ID               │
   508→│     · 注入到日志上下文，贯穿全链路追踪               │
   509→└──────────────────────┬──────────────────────────┘
   510→                       ▼
   511→┌─────────────────────────────────────────────────┐
   512→│  3. Rate Limiting Middleware                       │
   513→│     · 基于 Redis 的滑动窗口限流                     │
   514→│     · 全局限流 + 按 User / IP 分别限流              │
   515→│     · AI 接口单独限流（更严格的配额）                 │
   516→└──────────────────────┬──────────────────────────┘
   517→                       ▼
   518→┌─────────────────────────────────────────────────┐
   519→│  4. Auth Middleware (JWT)                          │
   520→│     · 从 Authorization Header 提取 Bearer Token   │
   521→│     · 验证签名、过期时间、黑名单                      │
   522→│     · 注入 current_user 到请求上下文                 │
   523→│     · 白名单路径跳过（/login, /health, /docs）       │
   524→└──────────────────────┬──────────────────────────┘
   525→                       ▼
   526→┌─────────────────────────────────────────────────┐
   527→│  5. Audit Logger Middleware                        │
   528→│     · 记录所有写操作（POST/PUT/DELETE）              │
   529→│     · 审计内容：操作人、操作类型、目标资源、变更摘要   │
   530→│     · 写入审计日志表（异步，不阻塞主流程）            │
   531→└──────────────────────┬──────────────────────────┘
   532→                       ▼
   533→┌─────────────────────────────────────────────────┐
   534→│  6. Error Handler                                  │
   535→│     · 全局异常捕获                                  │
   536→│     · 标准化错误响应格式                             │
   537→│     · 区分业务异常 / 系统异常 / 校验异常              │
   538→│     · 内部错误不暴露堆栈（生产环境）                  │
   539→└──────────────────────┬──────────────────────────┘
   540→                       ▼
   541→                 Router → Service → ...
   542→                       │
   543→                       ▼
   544→                 HTTP Response
   545→```

   549→## 5. AI Gateway 架构
   550→
   551→AI Gateway 是系统 AI 能力的统一接入层，屏蔽底层 LLM Provider 的差异，为上层业务提供一致的调用接口。
   552→
   553→```
   554→┌─────────────────────────────────────────────────────────────────┐
   555→│                       AI Gateway 架构                            │
   556→│                                                                  │

   558→│          │                                                       │
   559→│          ▼                                                       │
   560→│  ┌───────────────────────────────────────────────────────────┐  │
   561→│  │                  AIGateway (Facade)                        │  │
   562→│  │                                                           │  │
   563→│  │  统一接口:                                                 │  │
   564→│  │  · async chat(messages, model?, stream?) → AsyncIterator   │  │
   565→│  │  · async embed(texts, model?) → list[list[float]]          │  │

   567→│  │                                                           │  │
   568→│  │  内部能力:                                                 │  │
   569→│  │  · Provider 路由（根据配置选择当前激活的 Provider）          │  │

   575→│                            │                                    │
   576→│          ┌─────────────────┼─────────────────┐                  │
   577→│          ▼                 ▼                 ▼                  │
   578→│  ┌──────────────┐  ┌────────────┐  ┌──────────────────┐        │
   579→│  │ BaseProvider │  │ BaseProvider│  │  BaseProvider    │        │

   618→## 6. RAG 架构
   619→
   620→RAG（Retrieval-Augmented Generation，检索增强生成）是安诊保 AI 副驾的核心能力基础，确保 AI 回答基于权威知识库内容，而非「幻觉」。
   621→
   622→### 6.1 RAG Pipeline 全流程
   623→
   624→```
   625→═══════════════════════════════════════════════════════════
   626→                    离线索引流程（Ingestion Pipeline）
   627→═══════════════════════════════════════════════════════════
   628→
   629→文档上传 (PDF/Word/Excel/TXT/HTML)
   630→    │
   631→    ▼
   632→┌──────────────┐
   633→│ 1. 文档加载   │  支持格式：PDF、DOCX、XLSX、TXT、HTML、Markdown
   634→│   (Loader)   │  提取纯文本 + 元数据（标题、章节、页码）
   635→└──────┬───────┘
   636→       ▼
   637→┌──────────────┐
   638→│ 2. 文本解析   │  清洗噪音（页眉页脚、水印、目录）
   639→│   (Parser)   │  保留结构信息（标题层级、列表、表格）
   640→└──────┬───────┘
   641→       ▼
   642→┌──────────────┐
   643→│ 3. 文本分块   │  策略：
   644→│  (Chunking)  │  · 固定长度分块（chunk_size=512, overlap=64）
   645→│              │  · 语义分块（按段落/章节自然边界切分）
   646→│              │  · 混合策略（先按章节切分，超长章节再按固定长度切分）
   647→└──────┬───────┘
   648→       ▼
   649→┌──────────────┐
   650→│ 4. Embedding  │  调用 AI Gateway.embed()
   651→│   向量化      │  生成 1536 维向量（或模型默认维度）
   652→└──────┬───────┘
   653→       ▼
   654→┌──────────────────────────────────────────┐
   655→│ 5. 存入 PostgreSQL (pgvector)             │
   656→│    · 文档元数据表 (knowledge_documents)    │
   657→│    · 文档分块表 (knowledge_chunks)         │
   658→│      - chunk_text: 分块文本               │
   659→│      - embedding: vector(1536)            │
   660→│      - metadata: JSONB (来源、页码等)     │
   661→│      - document_id: 外键                  │
   662→│      - created_at: 时间戳                 │
   663→│    · 建立 IVFFlat / HNSW 索引加速检索       │
   664→└──────────────────────────────────────────┘
   665→
   666→═══════════════════════════════════════════════════════════
   667→                    在线查询流程（Query Pipeline）
   668→═══════════════════════════════════════════════════════════
   669→
   670→用户提问 (Query)
   671→    │
   672→    ▼
   673→┌──────────────────┐
   674→│ 1. Query 预处理    │  · Query 改写/扩展（可选，LLM 辅助）
   675→│                  │  · 意图识别（产品问答 / 话术生成 / 通用咨询）
   676→└──────┬───────────┘
   677→       ▼
   678→┌──────────────────┐
   679→│ 2. Query Embedding│  调用 AI Gateway.embed() 生成查询向量
   680→└──────┬───────────┘
   681→       ▼
   682→┌──────────────────────────────────────────────┐
   683→│ 3. Hybrid Search (混合检索)                    │
   684→│                                               │
   685→│  ┌─────────────────┐  ┌─────────────────────┐ │
   686→│  │ 向量检索 (ANN)   │  │ BM25 关键词检索      │ │
   687→│  │ pgvector        │  │ PostgreSQL FTS      │ │
   688→│  │ cosine similarity│  │ 全文搜索索引         │ │
   689→│  │ Top-K=20        │  │ Top-K=20            │ │
   690→│  └────────┬────────┘  └──────────┬──────────┘ │
   691→│           │                      │             │
   692→│           └──────────┬───────────┘             │
   693→│                      ▼                         │
   694→│           Reciprocal Rank Fusion (RRF)          │
   695→│           合并排序 → Top-K=10                   │
   696→└──────────────────────┬───────────────────────┘
   697→                       ▼
   698→┌──────────────────┐
   699→│ 4. Rerank 重排序  │  交叉编码器 (Cross-Encoder) 或 LLM 重排序
   700→│                  │  从 10 条精排到 5 条
   701→└──────┬───────────┘
   702→       ▼
   703→┌──────────────────┐
   704→│ 5. 权限过滤       │  · 用户角色/组织维度过滤
   705→│  (Post-Filter)   │  · 仅返回用户有权访问的知识条目
   706→└──────┬───────────┘
   707→       ▼
   708→┌──────────────────┐
   709→│ 6. Context 组装   │  将检索结果格式化为 LLM Context
   710→│                  │  包含：引用来源、分块内容、相关性分数
   711→└──────┬───────────┘
   712→       ▼
   713→┌──────────────────┐
   714→│ 7. LLM 生成       │  System Prompt + Context + User Query
   715→│                  │  流式输出（SSE）
   716→└──────┬───────────┘
   717→       ▼
   718→┌──────────────────┐
   719→│ 8. 引用溯源       │  在 AI 回答中标注引用的知识条目
   720→│  (Citation)      │  用户可点击查看原文
   721→└──────┬───────────┘
   722→       ▼
   723→┌──────────────────┐
   724→│ 9. 合规检查       │  合规引擎扫描 AI 回答
   725→│  (Compliance)    │  · 敏感词过滤
   726→│                  │  · 话术规范性检查
   727→│                  │  · 保险监管要求检查
   728→│                  │  · 不合规内容标记/拦截
   729→└──────┬───────────┘
   730→       ▼
   731→   返回最终结果给用户（流式 + 引用 + 合规标识）
   732→```
   733→
   734→### 6.2 RAG 关键设计决策
   735→
   736→| 决策点           | 选择                   | 理由                                                |
   737→| ---------------- | ---------------------- | --------------------------------------------------- |
   738→| 向量数据库         | PostgreSQL + pgvector  | 减少技术栈复杂度，与业务数据同库，事务一致性好，维护成本低    |
   739→| 分块策略           | 语义 + 固定长度混合     | 保险文档结构化程度高，需保留章节完整性                       |
   740→| 检索策略           | Hybrid Search (RRF)    | 向量检索捕获语义相似性，BM25 捕获关键词精确匹配，两者互补      |
   741→| 重排序             | Cross-Encoder          | 相比纯向量检索，显著提升 Top-K 精度                        |
   742→| Embedding 模型      | 复用 AI Gateway        | 统一管理，灵活切换                                       |
   743→

   916→## 9. 安全架构
   917→
   918→```
   919→┌─────────────────────────────────────────────────────────────────────┐
   920→│                         安全架构（Defense in Depth）                  │
   921→│                                                                      │
   922→│  第一层: 网络安全                                                     │
   923→│  ┌──────────────────────────────────────────────────────────────┐   │
   924→│  │  · HTTPS 全链路加密（TLS 1.2+）                                │   │
   925→│  │  · CORS 严格白名单                                              │   │
   926→│  │  · 安全响应头（X-Frame-Options, CSP, HSTS）                    │   │
   927→│  │  · DDoS 基础防护（Rate Limiting）                               │   │
   928→│  └──────────────────────────────────────────────────────────────┘   │
   929→│                                                                      │
   930→│  第二层: 身份认证 (Authentication)                                     │
   931→│  ┌──────────────────────────────────────────────────────────────┐   │
   932→│  │  · JWT Token 认证（Access Token + Refresh Token）               │   │
   933→│  │  · Access Token: 短期（15min），存储在内存                       │   │
   934→│  │  · Refresh Token: 长期（7d），存储在 HttpOnly Cookie             │   │
   935→│  │  · 密码: bcrypt 哈希存储（cost factor = 12）                     │   │
   936→│  │  · 登录失败限流（5 次/min，超出锁定 15min）                       │   │
   937→│  │  · Token 黑名单（Redis，登出时即刻失效）                          │   │
   938→│  └──────────────────────────────────────────────────────────────┘   │
   939→│                                                                      │
   940→│  第三层: 权限控制 (Authorization - RBAC)                               │
   941→│  ┌──────────────────────────────────────────────────────────────┐   │
   942→│  │  角色:                                                        │   │
   943→│  │  · admin        — 超级管理员（全部权限）                        │   │
   944→│  │  · manager      — 团队管理者（团队数据 + 业务功能）               │   │
   945→│  │  · agent        — 保险代理人（个人数据 + 业务功能）               │   │
   946→│  │  · viewer       — 只读用户（仅查看，无编辑权限）                   │   │
   947→│  │                                                               │   │
   948→│  │  权限粒度:                                                     │   │
   949→│  │  · 功能权限: 能否访问某模块（如 admin、community）               │   │
   950→│  │  · 数据权限: 能否访问某数据（仅本人 / 本团队 / 全部）            │   │
   951→│  │  · 操作权限: 能否执行某操作（增/删/改/查/导出）                  │   │
   952→│  └──────────────────────────────────────────────────────────────┘   │
   953→│                                                                      │
   954→│  第四层: 数据安全                                                     │
   955→│  ┌──────────────────────────────────────────────────────────────┐   │
   956→│  │  · 敏感字段脱敏（手机号: 138****1234, 身份证: 110***********1234）│   │
   957→│  │  · 数据库字段级加密（客户身份证号、银行账号）                     │   │
   958→│  │  · SQL 注入防护（SQLAlchemy ORM 参数化查询）                     │   │
   959→│  │  · XSS 防护（前端输出转义 + CSP Header）                       │   │
   960→│  │  · 文件上传安全（类型白名单、大小限制、病毒扫描预留）              │   │
   961→│  └──────────────────────────────────────────────────────────────┘   │
   962→│                                                                      │
   963→│  第五层: AI 安全                                                     │
   964→│  ┌──────────────────────────────────────────────────────────────┐   │

  1146→### 11.3 Demo 模式技术实现
  1147→
  1148→```python
  1149→# backend/app/core/config.py (示意)
  1150→class Settings(BaseSettings):
  1151→    demo_mode: bool = False
  1152→    ai_provider: str = "deepseek"  # demo_mode=True 时自动覆盖为 "mock"
  1153→
  1154→    @property
  1155→    def effective_ai_provider(self) -> str:
  1156→        return "mock" if self.demo_mode else self.ai_provider
  1157→
  1158→# backend/app/ai/gateway.py (示意)
  1159→class AIGateway:
  1160→    def __init__(self, settings: Settings):
  1161→        provider_name = settings.effective_ai_provider
  1162→        self.provider = self._create_provider(provider_name)
  1163→
  1164→# backend/app/main.py (示意)
  1165→@app.on_event("startup")
  1166→async def startup():
  1167→    if settings.demo_mode:
  1168→        await seed_demo_data()  # 自动导入 Seed 数据
  1169→```
